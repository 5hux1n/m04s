# 协议与型号映射

依据为开发时用户提供的印先森 App 4.46.0。仓库仅记录自行整理的协议结论、
最小测试参数和型号映射，不分发 App 或可执行文件。

## 设备选择

官方流程按型号选策略，必要时通过配置继承回退，再根据 SN／固件、DPI、
纸型等选择编码和控制参数。同型号也可能存在不同分支。
静态表包含 24 个策略类；[型号映射](model-strategies.json) 是开发线索，
并非已验证兼容设备表，也不代表 App 界面使用全部 SDK 产品线。

## 本项目 M04 路径

| 型号条件 | 官方图像编码选择 |
| --- | --- |
| M04S + Q171 或 Q466 前缀 | raw |
| M04S + 其他非空 SN，包括 Q016 | MiniLZO + 3 字节零尾部 |
| M04S + 官方上下文尚未取得 SN | raw；本项目自动模式选择停止而不是猜测 |
| M04AS / M04AH / Y04S | raw |

图像头为 `1d 76 30 00` 后接小端行字节数和高度。
MiniLZO 按 4096 原始字节分块，每块为小端压缩长度、零标记、压缩数据。
连续纸单图尾部为两次 `1b 64 02`；raw 不包含压缩分支的 3 个零。

Q016/Q171 的 M04S 在 53 mm 模式补左 6／右 18 点，80 mm 补右 32 点。
其他宽度的官方图像目标为 1260 像素；头部和点阵循环向下取整到 1256 点。
超出 1248 点内容上限的区域仅为全白补边。该路径需分别做纸面验证。

恢复的方法与分支地址：`QYM04Strategy imageDataWithPrintParams:image:`
的型号检查 `0x100d74870`、raw 调用 `0x100d748b4`、LZO 调用 `0x100d74934`；
补白位于 `handleImages:printParams:model:`。
SN 请求 `1f 11 09`，回应为 `1a 08` + 15 字节 SN；解析分支 `0x100d6a3a0`。
最小参数夹具在 `tests/fixtures/m04_profiles.json`。

## 传输和完成

- FF02 使用 Write Without Response，分包不超过 182 字节，并尊重协商上限。
- 每次控制／图像写入共享 FF03 额度及 macOS 发送缓存背压。
- FF03 `01 n` 返回额度；额度恢复仅代表缓存释放。
- FF01 `1a 0f 0c` 表示设备完成；完成后保留 1 秒收尾。
- 控制与点阵之间保留 15 ms 边界，不使用逐包固定延时。
- 断线、额度超时、无完成通知均报错，不自动重发未确认任务。

新批次若不符合此流控或完成检测，需要单独证据，不能用延时退出伪装成功。
`isSupportCompress` 等配置字段不能替代实际策略判断；原配置中的字面值
与已确认的 M04S LZO/BLE 路径并不总能直接对应。
